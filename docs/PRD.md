## 1. 背景与问题

### 1.1 用户

自助旅行者（1–4 人出行），用手机/电脑做行程规划，会在旅途现场临时改计划。

### 1.2 现状痛点

| # | 痛点 | 现象 |
|---|---|---|
| 1 | **聊完就丢** | 通用 AI 助手关掉页面什么都不剩，下次要重新讲一遍偏好 |
| 2 | **说了不做** | AI 回"已记住"，但用户没有任何界面能验证它到底改没改 |
| 3 | **通用问答答不到落地** | 问"附近吃啥"，得到一堆品类，没有具体店名和距离 |
| 4 | **行程改一处全乱** | 静态攻略是一段文本，"起晚了 2 小时"只能整段重写 |
| 5 | **多人偏好冲突** | 每个人的诉求没法对齐到同一份行程 |

### 1.3 问题陈述

> **同类产品的通病是"聊完就丢、说了不做"。**
> 本产品要让 AI 的「记住了」和「改好了」**都能在界面上当场验证**。

## 2. 目标与成功指标

### 2.1 产品目标

1. 对话式完成行程规划，并把**旅行资产沉淀下来**（行程 / 偏好 / 打卡 / 收藏 / 预算 / 游记）。
2. **记忆可见**：偏好写入后在回答末尾固定回显。
3. **动作可见**：真正写库的操作渲染成「本次为你做了 N 件事」卡片，读操作不生成。
4. **可回退**：行程节点化 + 版本快照 + 一键回退。
5. **边界清晰**：坐标只从会话取、模型无权指定；涉支付行为不做；模型异常降级。

### 2.2 成功指标（含口径）

| 指标 | 口径定义 | 目标 |
|---|---|---|
| 写操作可验证率 | 返回 `actions` 卡片的本轮写操作数 / 本轮实际写操作数 | 100% |
| 记忆可见率 | 带回显的偏好写入轮次 / 偏好写入轮次 | 目标 100%（**当前靠提示词约束，未代码强制**） |
| 会话可恢复率 | 重启后仍能看到历史话题的用户数 / 总用户数 | 100%（会话落库） |
| 距离可信率 | 空间类回答中给出真实米数的条数 / 空间类回答条数 | 100%（禁用"附近"这类模糊词） |
| 工具调用有效率 | 成功执行的工具调用 / 总工具调用 | 记录但不设硬指标；**30 个工具超出模型有效选择范围，是已知问题** |
| **反指标** | 不产出"伪成功"（没写库却回"已记住"） | 写操作与卡片一一对应 |

## 3. 用户流程

### 3.1 主流程

```
打开桌面端（Electron 自动拉起后端 + 内嵌数据库）
  → 登录（会话落库，重启恢复登录态）
  → 左侧选会话 / 新建会话（首条消息自动起标题）
  → 输入需求（如"帮我规划汕头 4 天"）
      └─ Agent 循环（最多 12 轮）：
           请求模型（带 30 个工具清单）
             ├─ 模型未调工具 → 直接返回文本答案，结束
             └─ 模型要调工具 → 后端 dispatch 执行
                   ├─ 读操作：查库 / 算距离，结果回填
                   └─ 写操作：写库 + 记入 actions 摘要
                   └─ 工具结果作为 role=tool 消息塞回历史，进入下一轮
  → 页面返回：answer（文本）+ actions（写操作卡片）+ sessionId
  → 行程页：时间线节点 / 版本历史 / 一键回退
```

### 3.2 异常分支

| 分支 | 触发 | 行为 |
|---|---|---|
| 未登录 / 未配 API Key | 请求入口 | 降级为简易模式（**需显式提示；当前为静默降级，已列为缺陷**） |
| 工具执行抛异常 | 工具内部 | 把错误信息作为 `role=tool` 结果回给模型，模型可自行纠正，不让接口 500 |
| 12 轮未收敛 | 循环上限 | 返回"规划超时，请把需求说得再具体一点" |
| 本地景点库查不到 | 检索类工具 | 走联网检索；检索不通只返回"暂时查不到"，**不编造** |
| 反查地名失败 | 位置引擎 | 如实说"拿到坐标但没解析出地名"，**绝不猜一个区 / 商圈** |
| 模型调用异常 | 任意轮次 | 降级为规则回复，不白屏 |

## 4. 范围

### 4.1 本期做

| 模块 | 内容 |
|---|---|
| 智能管家 | 30 个工具 · 12 轮调用循环 · 四大引擎（动态行程编排 / 偏好记忆 / GPS 现场向导 / 多人协同记录） |
| 多会话 | 新建 / 列表 / 重命名 / 删除 / 首条消息自动起标题 |
| 记忆 | 偏好写入回显；偏好档案（饮食 / 体力 / 环境 / 出行四类硬约束）+ 多套模板 |
| 行程 | 时间线节点（订单 / 预约 / 风险 / 备注 / 备选路线）、状态流转、版本快照与回退、预算绑定、行李清单 |
| 现场 | 逆地理编码、周边检索（5–10km）、路径规划、到达播报、内嵌一键导航 |
| 打卡与游记 | 地点 / 评分 / 耗时 / 备注 + 配图；基于打卡生成结构化游记 |
| 社交 | 动态广场、好友（ID 或邀请码）、他人主页按权限过滤 |
| 权限 | 动态 / 行程 / 打卡 / 收藏 / 点评共用 public · friends · private 三档 |
| 交付 | Electron 免安装版：内嵌 jlink 裁剪 JRE + 内嵌 H2，目标机免装 Java/MySQL |

### 4.2 明确不做

| 不做 | 理由 |
|---|---|
| **无人值守自动下单（涉支付）** | 涉及资金，风险不可控 |
| 不做景点百科 | 通用大模型答得更好，无差异化 |
| 不做通用游记生成器 | 差异化不足 |
| 不接 LangChain / MCP 等 Agent 框架 | 工具全在自建库里，直接写 Java 更可控；少一层抽象，出错好定位 |
| 不用 ORM | 手写 SQL 让"按 id 查必须带 `and username = ?`"这条越权约束**显式可见** |

## 5. 功能需求

| 编号 | 功能 | 描述 | 异常分支 | 验收标准 |
|---|---|---|---|---|
| FR-01 | 会话与登录 | 登录态写 `tomcat_sessions`，30 天有效 | 未登录 → 提示并降级 | 关掉桌面端重开，登录态与历史话题都在 |
| FR-02 | 多会话 | `chat_session` 管理；首条消息自动起标题 | 标题重复 → 允许 | 会话名能一眼认出话题（非"会话 1/2/3"） |
| FR-03 | 对话记忆 | `chat_message` 只存 user/assistant 纯文本 | 不存 `tool_calls`（回放会触发 400） | 加载上限 200 条；历史窗口 12 条 |
| FR-04 | Agent 循环 | 最多 12 轮；工具结果回填后继续推理 | 超轮次 → 明确提示 | 一次"改行程"链路（读→算→写）能在 12 轮内完成 |
| FR-05 | 写操作可见 | 写库操作生成 `actions` 摘要，前端渲染卡片 | 读操作**不生成** | 卡片出现即代表数据被改过 |
| FR-06 | 记忆回显 | 偏好写入后回答末尾固定回显（已记住：维度=取值） | 无新增偏好不回显；一条回答最多 1 次 | **回显与写入一一对应** |
| FR-07 | 行程节点化 | `trip_node` 五类节点；局部修改后可顺延后续 | — | "起晚了 2 小时"只需改受影响节点 |
| FR-08 | 版本与回退 | 每次修改自动存版本；`rollbackTrip` 一键回退 | — | 回退后可继续操作 |
| FR-09 | 空间与距离 | 基于会话上报 GPS 算真实距离，输出"约 X 米 / 公里 + 步行或打车建议" | 反查失败 → 如实说明 | **坐标只从会话取，模型无权指定**；禁用"附近"等模糊词 |
| FR-10 | 权限三档 | public / friends / private；非法值归一为 public | 越权访问 → 按权限过滤 | 过滤在后端做，改请求拿不到别人数据 |
| FR-11 | 打卡与游记 | 打卡可关联附近商户；游记基于打卡生成 | — | 打卡与动态相互独立 |
| FR-12 | 桌面交付 | Electron 拉起后端；免安装版内含 JRE 与内嵌库 | 找不到 Java → 给出可读提示而非崩溃 | 目标机不装 Java/MySQL 也能双击运行 |

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 带工具的请求比普通问答慢，前端需明示"可能需要几十秒"；单次工具输出设预算，防上下文爆炸 |
| 数据 | 默认内嵌 H2（MySQL 兼容模式），可用 `DB_URL` 覆盖为自有 MySQL |
| 安全 | 所有按 id 的查询显式带 `and username = ?`；坐标只认 session |
| 合规 | API Key 不进数据库，只放配置文件（本仓库默认带上可用 Key，保证开箱即用） |
| 兼容 | SQL 写成 MySQL / H2 双兼容方言 |
| 可维护 | 前端零构建（原生多页面），改一行即可上线；代价是暂无设计令牌化 |

## 7. 数据与埋点

| 数据 | 用途 | 存储 |
|---|---|---|
| 登录态 | 跨重启恢复 | `tomcat_sessions` |
| 话题 | 多会话 | `chat_session` |
| 消息 | 上下文 | `chat_message` |
| 行程节点 / 版本 | 动态行程与回退 | `trip_node` / `trip_version` |
| 偏好 / 同行人 / 收藏 / 预算 / 清单 / 打卡 / 游记 | 旅行资产沉淀 | 各自业务表 |

**埋点**：工具调用名 / 参数 / 结果摘要 / 耗时（后端日志）；本轮写操作清单（`actions`）。

## 8. 风险与依赖

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 1 | **未配 Key 时静默降级到旧桩** | 用户看不出区别但 Agent 能力全失效，会让人误判"产品不行" | **已列为最关键缺陷**：需显式提示"当前为简易模式" |
| 2 | 30 个工具超出模型有效选择范围 | 深层工具不易被触发 | 合并入口（用 `action` 参数承载细分），目标 30 → 约 12 |
| 3 | 回显靠提示词约束 | 模型可能不回显 | 应在代码层检测到 `savePreference` 即自动追加回显 |
| 4 | 回退后 AI 不自知 | 模型可能基于被回退内容继续推理 | 回退时写一条系统消息告知模型 |
| 5 | 外部依赖（高德 / 检索 / 大模型） | 不可用则功能受限 | 均需有降级路径，不编造 |

## 9. 上线与灰度

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| P0 | 单页原型 + 内嵌 H2 | 主流程可跑通 |
| P1 | 多页面重构（11 个业务页）+ 动态广场 / 好友 / 打卡 / 附近 / 偏好 / 账号 | 页面间导航无死角 |
| P2 | 会话落库 + 多会话 + 写操作卡片 | 重启不丢、动作可见 |
| P3 | 免安装版（内嵌 JRE + 内嵌库） | 干净机器双击可用 |

## 10. 已知缺陷（不掩盖）

1. **密码明文存储**（应改 BCrypt）。
2. **30 个工具未合并**，深层工具触发率低。
3. **自动登录未实现**：勾选框读 `value` 而非 `checked`，形同虚设。
4. **多个功能有后端无独立入口**：游记 / 时间线 / 版本回退 / 同行人。
5. **无单元测试**，全靠手工验证；`dispatch` 的 30 个分支没有覆盖。

## 11. 后续迭代（按优先级）

| # | 迭代项 | 理由 |
|---|---|---|
| 1 | 降级时界面显式横幅 + "去配置"入口 | 避免用户测了一个没有 Agent 的版本 |
| 2 | 写操作卡片与回显改成代码强制 | 把"看起来做了"变成"确实做了" |
| 3 | 工具合并到约 12 个 | 提升模型选择准确率 |
| 4 | 密码改 BCrypt | 安全底线 |
| 5 | 给 `dispatch` 补单测 | 30 个分支全靠手工验证不可持续 |
