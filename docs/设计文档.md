## 二、Agent 循环

**公式**：`Agent = LLM（大脑）+ Tools（手脚）+ Loop（循环）+ Memory（记忆）`

```java
for (int round = 0; round < MAX_ROUNDS; round++) {   // MAX_ROUNDS = 12
    raw = aiChatService.chatWithTools(messages, toolsJson);
    JsonNode toolCalls = message.path("tool_calls");

    if (toolCalls 为空) {
        return 最终答案;                    // 模型认为可以收尾了
    }
    messages.add(message);                 // 把模型的调用请求放进历史

    for (JsonNode call : toolCalls) {
        String result = dispatch(username, toolName, arguments, lat, lng);
        // 写操作记一条摘要，供前端渲染动作卡片
        if (WRITE_TOOLS.contains(toolName)) actions.add(describeAction(...));

        ObjectNode toolMessage = textMessage("tool", result);
        toolMessage.put("tool_call_id", callId);   // 必须回填，否则厂商报 400
        messages.add(toolMessage);
    }
}
```

### `MAX_ROUNDS = 12` 的依据

一次「行程变更」的完整链路：

```
listPreferences（读画像）      → 轮1
listTripNodes（读现有节点）     → 轮2
查开放 / 预约时间               → 轮3
算通勤是否来得及                → 轮4（可能还要 searchWeb 查备选）
saveTripNode（写回节点）        → 轮5
setTripStatus / 输出风险清单    → 轮6
```

**原值 6 刚好够「读一遍」，不够「算一遍 + 写回去」** —— 表现为
「AI 给了一段文字建议，但数据一个字都没变」。改为 12 后正常。

## 三、三层会话存储

**这是本项目最关键的设计决定。**

| 层 | 表 / 位置 | 存什么 | 失效后果 |
|---|---|---|---|
| **HTTP 会话** | `tomcat_sessions` | 登录态（`loginUser`） | 要重新登录 |
| **会话列表** | `chat_session` | 有哪几个话题（标题、时间） | 话题列表丢失 |
| **消息** | `chat_message` | 每个话题里的消息 | 上下文丢失 |

**为什么分三层**：把「用户是谁」「有哪几个话题」「每个话题聊了什么」拆开，
任何一层失效都不影响另外两层。

### 会话持久化实现

```java
// config/SessionConfig.java
JDBCStore store = new JDBCStore();
store.setDriverName(DB_DRIVER);
store.setConnectionURL(DB_URL);
store.setConnectionName(DB_USER);
store.setConnectionPassword(DB_PASSWORD);
store.setSessionTable("tomcat_sessions");
store.setSessionIdCol("session_id");
store.setSessionDataCol("session_data");
store.setSessionValidCol("valid_session");     // 注意：不是 is_valid
store.setSessionMaxInactiveCol("max_inactive");
store.setSessionLastAccessedCol("last_access");
store.setSessionAppCol("app_name");

PersistentManager manager = new PersistentManager();
manager.setStore(store);
manager.setMaxIdleSwap(1);          // 闲置 1 分钟换出到库
manager.setMaxIdleBackup(0);        // 定期备份，防强杀丢数据
manager.setMinIdleSwap(-1);         // 不因内存压力随手换出
manager.setSaveOnRestart(true);     // 关闭时存下来
```

**表结构**（Tomcat 9 五列，与 Spring Boot 2.7.18 对应）：

```sql
create table if not exists tomcat_sessions (
    session_id     varchar(100) not null primary key,
    valid_session  char(1)      not null,
    max_inactive   int          not null,   -- 毫秒
    last_access    bigint       not null,
    app_name       varchar(255) null,
    session_data   mediumblob   null,       -- 序列化后的会话
    key kapp_name (app_name)
) default charset=utf8mb4;
```

> Tomcat 10 起改成三列（`session_id` / `session_data` / `is_valid`），不能混用。

## 四、四个必须记住的坑

### 坑 1：`tool_call_id` 必须回填

```java
toolMessage.put("tool_call_id", callId);
```

不一致或缺失 → **厂商直接返回 400**。这不是可选字段。

### 坑 2：编译必须带 `-parameters`

Spring Boot 父 POM 默认给 javac 加 `-parameters`。手写构建命令时漏掉会导致：

```
IllegalArgumentException: Name for argument of type [java.lang.String] not specified,
and parameter name information not found in class file either.
```

**表现为所有带 `@RequestParam` 的接口全部 500。**

### 坑 3：Spring Boot fat jar 需要目录条目

手工重打 fat jar 时，必须把 `BOOT-INF/classes/` 及其子目录的**目录条目**也写进去。
缺失会报 `ClassNotFoundException: com.iflytek.chatgpt.Application`
（Tomcat/Spring Boot 的 `JarFileArchive` 靠目录条目扫描 classpath）。

### 坑 4：会话 cookie 的 maxAge 设置时机

在 `postProcessContext` 里改 cookie 会抛：

```
IllegalStateException: Property [max age] cannot be added to SessionCookieConfig
for context [/chat] as the context has been initialised
```

**必须在上下文初始化前**，经由工厂设置。

## 五、数据模型（23 张表）

| 域 | 表 |
|---|---|
| **会话** | `chat_session` · `chat_message` · `tomcat_sessions` |
| **行程** | `trip` · `trip_node` · `trip_version` |
| **偏好** | `user_preference` · `preference_template` · `preference_item` |
| **轨迹** | `travel_log` · `travelog` |
| **收藏** | `favorite_folder` · `favorite_item` |
| **工具箱** | `toolbox_document` · `packing_template` · `budget_entry` |
| **协同** | `trip_companion` |
| **位置** | `spot` · `spot_guide` |

全部由 `AgentSchemaInitializer` 用 `create table if not exists` 在启动时建好：
**只做新增，已存在的表和数据都不动；数据库不可用时仅告警，不影响启动。**

## 六、安全约定

| 约定 | 说明 |
|---|---|
| **身份只从 session 取** | `ChatController.currentUser(session)`，绝不由前端或模型传入 |
| **坐标只从 session 取** | 模型无权指定经纬度，否则「附近」就是模型随便挑的点 |
| **越权防护用双条件** | 所有按 id 查询的 SQL 都带 `and username = ?` |
| **SQL 全用占位符** | `PreparedStatement`，不做字符串拼接 |
| **工具异常不抛给用户** | `dispatch` 内 catch 后转成 JSON 错误返回给模型，让它自己纠正，避免接口 500 |
