# 一、一张图看懂四者关系

**它们不是并列的四个东西，是「一个东西 + 三层壳」。**

```
        ┌──────────────────────────────────────────────┐
        │         你写的产品（用户看到的东西）             │
        └──────────────────────────────────────────────┘
                            ▲
        ┌──────────────────────────────────────────────┐
  ③     │   HARNESS（驾驭层）                           │
        │   "怎么把 LLM 稳定、安全地用起来"的那整套代码    │
        └──────────────────────────────────────────────┘
                            ▲
        ┌──────────────────────────────────────────────┐
  ②     │   AGENT（智能体）                             │
        │   = LLM + 工具 + 循环 + 记忆                  │
        └──────────────────────────────────────────────┘
                            ▲
        ┌──────────────────────────────────────────────┐
  ①     │   LLM（大语言模型）                            │
        │   一个无状态的函数：文字进 → 文字出              │
        └──────────────────────────────────────────────┘

  ④  MCP 是一个「插头标准」—— 它不属于上面任何一层，
     它是让 ② 能接上外部工具/数据的一种通用接口协议。
```

**一句话理解:**

> **LLM 是发动机，Agent 是装了轮子和方向盘的车，Harness 是刹车、安全带、仪表盘和交规，MCP 是充电桩的通用接口。**

# 二、第 ① 层：LLM —— 它就是个"函数"

## 2.1 最该建立的直觉

**LLM 是一个无状态函数:**

```
输入：一段文字（prompt / messages）
输出：一段文字（completion）

就这么多。
```

## 2.2 它有三个"不会"，这三个不会决定了后面所有事

| LLM 不会 | 后果 | 谁来补 |
|---|---|---|
| **不会记事** | 每次调用都是全新的，不记得上一句 | Harness / Agent 的 Memory |
| **不会动手** | 它只能说"你应该去查数据库"，**不能真去查** | Agent 的 Tools |
| **不会自己循环** | 它答一次就结束了 | Agent 的 Loop |

## 2.3 你的项目里 LLM 在哪

`AiChatService.java` 的 `chat()` 方法，**整个方法就在干这一件事:**

```java
ObjectNode body = objectMapper.createObjectNode();
body.put("model", model);
body.put("temperature", 0.7);
ArrayNode messages = body.putArray("messages");
messages.addObject().put("role", "system").put("content", SYSTEM_PROMPT);  // 拼输入
messages.addObject().put("role", "user").put("content", userMessage);      // 拼输入

HttpRequest request = ...  // 发出去
HttpResponse<String> response = httpClient.send(request, ...);

JsonNode content = objectMapper.readTree(response.body())
        .path("choices").path(0).path("message").path("content");
return content.asText();   // 拿回文字
```

## 2.4 ⚠️ 一个必须记住的区分

| | 是什么 |
|---|---|
| **LLM** | 远端那个模型（`deepseek-flash`） |
| **调用 LLM 的代码** | 你写的 `AiChatService` ← **这已经是 Harness 的雏形了** |

> **`AiChatService` 不能叫 LLM。它是"调用 LLM 的代码"。**
> **这个区分建立不起来，后面四个词会一直乱。**

# 三、第 ② 层：Agent —— 给 LLM 装上"手脚"和"循环"

## 3.1 一个公式

```
Agent = LLM（大脑） + Tools（手脚） + Loop（循环） + Memory（记忆）
```

## 3.2 为什么加这四个东西就叫 Agent 了

| 组件 | 缺了它会怎样 | 有了它会怎样 |
|---|---|---|
| **LLM** | 没法理解人话 | 理解意图 |
| **Tools** | 只能"说"，不能"做" | **能真的去查数据库、写数据** |
| **Loop** | 问一次答一次 | **想 → 用工具 → 看结果 → 再想 → 直到完成** |
| **Memory** | 每轮都失忆 | 记得上一轮聊了什么、调过什么工具 |

## 3.3 分水岭就是 Tools

**判断一个东西是不是 Agent，只看一件事:模型能不能"决定去调用某个函数"。**

| | 普通 LLM 调用 | Agent |
|---|---|---|
| **模型输出** | 一段文字 | 可能是"**我要调用 `searchDestination`(keyword="三亚")**" |
| **谁来执行** | 没人，就是文字 | **你的 Java 代码** |
| **执行完干嘛** | 结束 | **把结果塞回去，再问模型一次** |

## 3.4 你的项目里已经有 Agent 的完整设计

`技术提炼.md` 里写的 `TravelAgentService.run()` **就是 Agent 循环:**

```java
private static final int MAX_ROUNDS = 5;   // ★ 必须设上限，防止死循环烧钱

public String run(String username, String userInput) {
    List<JsonNode> messages = new ArrayList<>();
    messages.add(systemMsg("你是旅行规划助手，可以调用工具查景点、存行程。"));
    messages.add(userMsg(userInput));

    for (int round = 0; round < MAX_ROUNDS; round++) {
        String raw = aiChatService.chatWithTools(messages, TOOLS_JSON);  // ← 问模型
        JsonNode choice = read(raw).path("choices").path(0);
        JsonNode message = choice.path("message");

        // 情况 A：模型没调工具，直接给了最终回答 → 结束
        if (message.path("tool_calls").isMissingNode()
                || !message.path("tool_calls").isArray()) {
            return message.path("content").asText();
        }

        // 情况 B：模型要调工具 → 把它的"调用请求"原样放进历史
        messages.add(message);

        for (JsonNode call : message.path("tool_calls")) {
            String toolName = call.path("function").path("name").asText();
            JsonNode args = read(call.path("function").path("arguments").asText());

            String result = dispatch(username, toolName, args);   // ★ 这里才是"真正干活"

            // 把执行结果作为 role=tool 的消息塞回历史，模型下一轮才能看到
            messages.add(toolMsg(call.path("id").asText(), result));
        }
        // 循环继续：带着工具结果再问一次模型
    }
    return "规划超时，请把需求说得再具体一点～";
}
```

### 画出来是这样

```
用户提问
   │
   ▼
┌────────────────────────┐
│ 问模型（带上工具清单）    │◄─────────────┐
└───────────┬────────────┘              │
            ▼                           │
     模型要调工具吗？                     │
      │是              │否               │
      ▼                ▼                │
 执行 Java 工具    返回文字答案           │
 （查库/写库）       （结束）             │
      │                                 │
      └── 结果塞回 messages ─────────────┘
```

> **这个"塞回去再问一次"的动作，就是 Agent 和普通调用的唯一区别。**

## 3.5 工具的"说明书"长什么样

**工具的本质 = 一个 Java 方法 + 一段给模型看的 JSON Schema。**

```json
{
  "type": "function",
  "function": {
    "name": "searchDestination",
    "description": "根据关键词（城市名、景点名、分类如'滨海度假'）搜索旅游目的地",
    "parameters": {
      "type": "object",
      "properties": {
        "keyword": { "type": "string", "description": "搜索关键词" }
      },
      "required": ["keyword"]
    }
  }
}
```

> **`description` 这句话是决定模型"什么时候用这个工具"的唯一依据。**
> **写得含糊，模型就不会用；写清楚，模型才调得对。**

# 四、第 ③ 层：Harness —— 最容易糊涂的一个词

## 4.1 一句话定义

> **Harness = "把 LLM 稳定、安全、可控地用起来"的那一整套工程代码。**

中文常译「**驾驭层**」或「**马具**」—— 这个词选得很准:

> **LLM 是一匹很有力气但不受控的马。Harness 就是马具 + 缰绳 + 车架，让它能拉车而不把人甩下去。**

## 4.2 为什么需要它 —— 因为裸 LLM 没法直接用

| 裸 LLM 的问题 | Harness 负责解决 |
|---|---|
| 无状态，不记得上文 | **拼上下文**（把历史消息组织好再发） |
| 上下文窗口有限 | **截断 / 压缩 / 摘要**旧消息 |
| 输出格式不确定 | **约束输出**（要求 JSON、校验、失败重试） |
| 可能幻觉 | **事实注入 / 引用来源 / 禁止编造** |
| 会调工具但不会执行 | **执行工具 + 把结果喂回** |
| 可能死循环烧钱 | **轮次上限、超时、熔断** |
| 可能被注入 | **不可信内容包裹、出站脱敏** |
| 出错就挂 | **重试 / 降级 / 兜底** |
| 看不见发生了什么 | **日志、追踪、成本统计** |

## 4.3 ⭐ 关键区分：Agent 是 Harness 的一部分

**很多人以为 Agent 和 Harness 是两回事。其实不是:**

```
Harness（整套驾驭层）
 ├── 上下文组装 / 截断
 ├── 工具定义与执行          ┐
 ├── 循环控制（= Agent Loop）  ├─ 这几样合起来，就叫 Agent
 ├── 记忆管理                ┘
 ├── 输出约束与校验
 ├── 安全边界（注入防护）
 ├── 降级 / 重试 / 熔断
 └── 日志与成本统计
```

> **Agent 是 Harness 里"能自己调工具"的那部分能力。**
> **Harness 是更大的概念** —— 它还包括"怎么拼 prompt""怎么防注入""超了怎么办"。

## 4.4 你的项目里 Harness 已经做了不少

### 案例 A：对话式产品的 LLM 接入

| Harness 该管的 | 你在哪做了 |
|---|---|
| 读配置、拼请求 | `AiChatService.chat()` |
| **人设约束**（别答成通用百科） | `SYSTEM_PROMPT`（"你是「旅行管家」，一位专业的中文旅行规划顾问…"） |
| **厂商可切换** | 换 `ai.base-url` 等三行即可，代码自动补 `/chat/completions` |
| **未配置时兜底** | `isConfigured()` 三项缺一 → 走本地模板，**保证 demo 不挂** |
| **异常降级** | `catch` → 返回"抱歉，AI 服务暂时不可用" |
| **超时控制** | `connectTimeout=10s` / 请求 `timeout=60s` |
| **轮次上限** | `MAX_ROUNDS = 5`（防死循环烧钱） |
| **越权防护** | `username` 只从 `session` 取，**不让模型或前端传** |
| **上下文记忆** | 建议把 `messages` 存进 `HttpSession` |

> **你已经在做 Harness 的事了，只是没叫这个名字。**

### 案例 B：FaultDetect

| Harness 该管的 | FaultDetect 里 |
|---|---|
| **降级** | LLM 层默认关闭，六条异常路径**全部降级为规则结论** |
| **默认保守** | 默认关闭 + 按需触发 |
| **安全默认值** | `insecure-tls` 默认 `false` |
| **边界** | 高风险动作必经人工确认 |
| **零假成功** | 异常状态记为 `degraded`，**不产出看起来像成功的产物** |

> **"拔掉模型接口还能出完整结论" —— 这是一个极其成熟的 Harness 设计。**

# 五、第 ④ 层：MCP —— 一个"插头标准"

## 5.1 一句话定义

> **MCP（Model Context Protocol）= 让 AI 应用统一接上外部工具和数据源的接口标准。**

**它解决的是"每接一个工具就要重写一遍"的问题。**

## 5.2 没有 MCP 的世界

```
你的 Agent ──┬── 接数据库   → 自己写一套 schema + 执行代码 + 异常处理
             ├── 接文件系统 → 又写一套
             ├── 接飞书     → 再写一套
             └── 接 GitHub  → 还得写一套
```

## 5.3 有 MCP 的世界

```
你的 Agent ──[MCP 协议]──┬── MCP Server（数据库）
                         ├── MCP Server（文件系统）
                         ├── MCP Server（飞书）
                         └── MCP Server（GitHub）

Agent 只管"我要调什么"，Server 自己实现"怎么调"
```

## 5.4 打个比方（这个比方最准）

| 现实世界 | AI 世界 |
|---|---|
| **USB 接口标准** | **MCP** |
| U 盘 / 键盘 / 打印机 | MCP Server（各种工具） |
| 电脑 | 你的 Agent / AI 应用 |

> **以前每个设备一个专用接口，有了 USB 之后统一了。MCP 就是 AI 工具的 USB。**

## 5.5 它和 Agent 的关系

```
Agent 要调工具
    │
    ├─ 方式一：工具写在自己代码里（你现在这样）
    │         TravelTools.searchDestination()
    │
    └─ 方式二：工具在远端，通过 MCP 协议调
              mcpClient.call("database", "query", {...})
```

**两种都行。MCP 的好处是"工具可以换、可以复用、别人写好的你直接用"。**

## 5.6 你现在需要 MCP 吗

**暂时不需要。**

| 你的现状 | 结论 |
|---|---|
| 只有 3 个工具（搜景点 / 存行程 / 列行程） | 直接写 Java 方法更简单 |
| 工具都在自己的库里 | 没有跨进程调用的必要 |

**什么时候需要:**

| 触发条件 | 说明 |
|---|---|
| 工具数量变多（10+） | 手工维护 schema 会失控 |
| 需要接现成的第三方工具 | 比如直接接 GitHub、浏览器、数据库客户端 |
| 要让别人的 AI 应用也能用你的工具 | 标准化接口才有价值 |

# 六、怎么"正确使用"：从你的项目出发的五步

## 6.0 你现在在哪一层

```
你的对话式产品：
  ① LLM 调用        ✅ 已经做了（AiChatService）
  ② Agent           🟡 文档里设计了，还没写代码
  ③ Harness         🟡 做了一部分（降级、超时、人设、轮次上限）
  ④ MCP             ❌ 不需要

你的 FaultDetect：
  ① LLM 调用        ✅ 做了（LlmAdvisor，但默认关闭）
  ② Agent           ❌ 刻意不做（结论必须来自规则引擎）
  ③ Harness         ✅ 做得很成熟（全路径降级、安全默认、边界控制）
  ④ MCP             ❌ 不需要
```

> **注意 FaultDetect 的取舍:它故意不用 Agent —— 因为"结论不能依赖模型"是它的核心主张。**
> **这说明你已经有产品判断了:不是所有东西都该往上堆。**

## 第一步：先接受"LLM 只是个函数"

**这一步没建立，后面全乱。**

| 别指望 | 要自己做 |
|---|---|
| 别指望它记事 | 自己维护 `messages` 列表 |
| 别指望它动手 | 自己写工具方法 |
| 别指望它一次答对 | 准备好校验与重试 |

## 第二步：把 Agent 跑通（最小版本）

**就做一件事:让模型能调一个工具。**

```
工具：只有一个 searchDestination(keyword)
循环：最多 3 轮
```

**验证方法（你文档里已经写了）:**

| 步骤 | 做法 | 看到什么才算成功 |
|---|---|---|
| 1 | 问"帮我找找三亚有哪些景点" | **后端日志出现 `searchDestination` 执行记录** |
| 2 | 再问"把刚才的行程存起来" | 数据库 `select * from trip order by id desc limit 5;` 能看到新记录 |

> ⭐ **日志里出现了，才是真的跑通了。看不到日志就等于没跑通。**
>
> **这一步是最关键的。一天跑通一个工具，胜过看十篇教程。**

## 第三步：补 Harness 的"保命三件套"

**先只补三个，别贪多:**

| # | 保命项 | 不做的后果 | 怎么写 |
|---|---|---|---|
| **1** | **轮次上限** | 死循环，**一直烧钱** | `for (round < MAX_ROUNDS)`，超了返回提示 |
| **2** | **工具执行 try-catch** | 工具一抛异常整个接口 500 | 把错误信息当 `role=tool` 的结果喂回模型，**让它自己纠正**（比如换个关键词再查） |
| **3** | **超时** | 前端一直转圈，用户以为死了 | `connectTimeout` + 请求 `timeout`；前端 loading 文案写"可能需要几十秒" |

## 第四步：再补两件"成熟度"的事

| # | 事项 | 为什么 |
|---|---|---|
| **4** | **越权防护** | 凡是带用户数据的工具，`username` **必须后端从 `session` 取，绝不能让模型或前端传** ← 你 `TripController` 已经是这个写法，照抄即可 |
| **5** | **成本与延迟的边界** | 带工具的请求比普通问答**慢、贵**（要"先思考再调用"） |

> ⚠️ **这条边界很重要:能一次问完的别用 Agent，需要"查数据 + 多步推理"才用。**

## 第五步：最后才考虑 MCP

**当工具超过 10 个、或者需要接现成第三方工具时再上。**

# 七、速查表与三句话总结

## 7.1 速查表（建议存下来）

| 概念 | 一句话 | 判断标准 | 你的项目 |
|---|---|---|---|
| **LLM** | 文字进文字出的函数 | 无状态、不会动手、不会循环 | `deepseek-flash` / `deepseek-chat` |
| **Agent** | LLM + 工具 + 循环 + 记忆 | **模型能不能决定调用函数** | `TravelAgentService`（已设计） |
| **Harness** | 把 LLM 用稳用安全的那套代码 | **超时/降级/截断/防注入写在哪** | `AiChatService` + `isConfigured()` 降级 |
| **MCP** | AI 工具的 USB 接口标准 | **工具是不是在外部、数量多不多** | 不需要 |

## 7.2 三句话总结

> **① LLM 是函数:无状态、不会动手、不会循环。**
>
> **② Agent 就是给它装上手脚（Tools）和循环（Loop）—— 分水岭是"模型能不能决定调用函数"。**
>
> **③ Harness 是把这一切用稳的那层工程代码 —— Agent 只是 Harness 里"能调工具"的那部分能力。**

## 7.3 一个更短的记法

```
LLM      = 大脑（只会想）
Agent    = 大脑 + 手脚 + 循环 + 记忆（会想也会做）
Harness  = 缰绳 + 刹车 + 仪表盘（让它别闯祸）
MCP      = USB 接口（换工具的通用插座）
```

# 附录 A · 常见混淆对照

| 常见说法 | 问题 | 正确理解 |
|---|---|---|
| "我的 LLM 服务写好了" | 把"调用 LLM 的代码"叫成 LLM | 那是 **Harness 的一部分** |
| "Agent 就是高级的 prompt" | 忽略了 Tools 和 Loop | **没有工具调用就不是 Agent** |
| "Agent 和 Harness 是一回事" | 层级搞混了 | **Agent ⊂ Harness** |
| "用了 MCP 才是 Agent" | 因果反了 | **MCP 只是接工具的一种方式，和是不是 Agent 无关** |
| "模型说它查了数据库" | 模型不会动手 | **模型只会说"我要查"，执行的是你的代码** |
| "上下文越长越好" | 成本和延迟都会涨 | **Harness 要负责截断与压缩** |
| "接了模型就是 AI 产品" | 跳过了 Harness | **降级、边界、可控才是产品** |

# 附录 B · 你项目里那 8 条踩坑清单（原文摘录）

> 来自你自己的 `技术提炼.md` 第 8 节。**这些是真正跑过才会知道的坑。**

| # | 坑 | 说明 |
|---|---|---|
| 1 | **一定要设 `MAX_ROUNDS`** | 模型可能反复调工具，不设上限会一直循环、一直扣钱 |
| 2 | **工具执行必须 try-catch** | 工具抛异常时把错误当 `role=tool` 结果返回，模型能自己纠正，而不是整个接口 500 |
| 3 | **`arguments` 是字符串不是对象** | `call.function.arguments` 拿到的是 JSON **字符串**，必须再 `readTree()` 解析一次 |
| 4 | **`tool_call_id` 必须回填** | 构造 `role=tool` 消息时，`tool_call_id` 要和模型给的 `id` 完全一致，否则厂商直接报 400 |
| 5 | **越权防护** | 凡是带用户数据的工具，`username` 必须由后端从 `session` 取，**绝不能让模型或前端传** |
| 6 | **成本与延迟** | 带工具的请求比普通问答慢、贵。**能一次问完的别用 Agent** |
| 7 | **超时** | Agent 循环总耗时是各轮之和，前端 loading 文案要说明"可能需要几十秒" |
| 8 | **配置为空要兜底** | 三项配置缺任何一项就走本地模板，保证 demo 不挂 |

# 附录 C · 一句话回答可能的面试提问

| 面试官问 | 怎么答 |
|---|---|
| **"LLM 和 Agent 什么区别？"** | "LLM 是个无状态函数，只会说不会做。**Agent 是给它装上工具和循环 —— 分水岭是模型能不能决定调用函数。**" |
| **"Harness 是什么？"** | "**把 LLM 用稳的那层工程代码**:上下文怎么拼、超了怎么截断、工具怎么执行、出错怎么降级、怎么防注入。**Agent 只是其中'能调工具'的那部分能力。**" |
| **"你用 MCP 了吗？"** | "**目前不需要** —— 我只有 3 个工具且都在自己库里，直接写方法更简单。**工具超过 10 个或要接第三方时再上 MCP。**" |
| **"你怎么保证 Agent 不乱来？"** | "三道:**轮次上限**防死循环烧钱、**工具 try-catch** 让模型自己纠正而不是接口 500、**越权防护**上 `username` 只从 session 取。" |
| **"你怎么知道 Agent 真的生效了？"** | "**看后端日志有没有工具执行记录。** 日志里没出现，等于没跑通。" |
