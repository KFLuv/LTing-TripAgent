# LTing 真人用户验收脚本

状态：**等待 1–2 名真实用户执行**。本文件不伪造用户结果。

## 目标

验证用户是否能独立完成“规划 → 修改 → 确认 → 回退”，并记录首次使用中的卡点。

## 参与者

- 用户 A：有真实出行规划需求。
- 用户 B：无明确出行目标，只给定城市和两天时间。

## 测试规则

- 不提前讲功能位置。
- 不替用户操作。
- 只记录用户原话、操作路径、等待时间和错误。
- 不把工作人员判断当成用户结论。

## 任务

1. 输入目的地、天数和一个偏好，生成行程。
2. 在行程本中确认正文和节点已保存。
3. 修改第二天下午安排，确认是修改原行程而不是新建重复行程。
4. 查看版本并回退一次，确认正文和节点都恢复。
5. 询问一个实时事实（如当日排队时间），确认系统不编造。
6. 使用一次预算或偏好写入，确认动作反馈可见。

## 判定

- 两名用户均能在无提示下完成核心闭环：通过。
- 任一人无法找到修改或回退入口：失败。
- 出现伪成功、越权、错误导航或数据丢失：阻断发布。
