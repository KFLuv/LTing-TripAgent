# LTing 2.0.2 - Click-first Agent Travel Workbench

发布日期：2026-11-18
上一正式版本：`v1.1.9`
发布范围：`v1.1.9 → v2.0.2`

## 版本定位

LTing 从“对话优先的旅行助手”重构为“Click-first 的 Agent 旅行工作台”：

```text
旧：Type-first
输入一句需求 → 等模型生成 → 得到一段文本 → 再手工修改

新：Click-first + Agent execution
选目的地与时间 → 点选候选地点 → 规则校验 → 生成可编辑行程
→ 点击或 AI 产生结构化 Operation → Preview → 用户确认 → Apply → 可回退版本
```

AI 不再是唯一入口，也不再直接改数据库。AI 和点击操作共用同一份旅行状态、同一套 PlanOps、同一套规则校验和同一个版本系统。

## 从 v1.1.9 到 2.0.2 的主要变化

### 1. 产品主线重构

- 主入口从聊天框改为“出行工作台 → 目的地与时间 → 候选地点 → 行程编辑”。
- AI 收进右下角气泡，作为自由表达、异常处理和结构化操作入口。
- 增加固定目的地摘要、已选候选数量和连续选点反馈。
- 把高级预算、交通、偏好和权重折叠，降低首屏信息密度。
- 统一“地图、候选、行程、版本和 AI”围绕同一份 canonical plan data 工作。

### 2. PlanOps 受控执行链

- 新增 `plan_context`、`plan_operation`、`trip_version` 等状态与审计能力。
- 新增 Context → Preview → Apply 执行链。
- 支持 `MOVE_NODE / REMOVE_NODE / REPLACE_NODE / REORDER_NODE / LOCK_NODE`。
- 支持候选增删、新增节点、临时闭馆、整份行程重建和路线耗时写回。
- 支持目的地、日期、天数、人数、节奏、交通、预算、住宿和长期偏好更新。
- Apply 时二次校验用户、版本、Token、预算和偏好，过期 Context 会被拒绝。
- 同一 `operationId` 不会重复执行。
- 每次 PlanOps Apply 生成操作前后版本，可撤销或回退到指定版本。
- AI 不能再直接写 `plan_data`；旧写入接口遇到 PlanOps 行程会被拦截。

### 3. 候选池与选点体验

- 新增 `trip_candidate` 候选池与候选版本快照。
- 候选支持按类型、美食细分、区域和推荐方式筛选。
- 选择候选后保持筛选上下文，支持连续选择多家餐厅和地点。
- 默认展示 60 个点位，显示筛选总数，并支持分批展开和一键显示全部。
- 增加目的地锚点周边搜索，可搜索“双廊古镇”这类县、镇、村和景区级范围。
- 过滤客栈、停车场、厕所、政府机构等非游玩设施。
- 候选加入后进入 PlanOps，点击和 AI 使用同一套候选规则。

### 4. 行程约束与优化

- 新增 Day Optimize：少折返、缩短停留和组合方案。
- 支持驾车、步行、骑行和公交四种路线模式。
- 路线优先使用高德真实距离，失败时显式降级为估算。
- 新增 Plan Critic，汇总跨天时间、距离、营业、预算和偏好冲突。
- 支持营业时间、多时间段、星期闭馆、临时闭馆和未知营业时间标记。
- 增加城际交通、去程/返程、接驳和首尾日可用时间扣减。
- “第一天是否计入出发交通”已进入排序与行程可行性判断。
- 增加节假日、周末和高人流日避峰逻辑。
- 增加预算分项、已用/剩余、超支冲突和低成本替代候选。

### 5. 空间、路线与地图

- 新增候选空间聚类、住宿区域通勤评分和逐日路线矩阵。
- 新增路线耗时与距离写回正式行程节点。
- 50 点以上地图聚合，支持点位反向高亮、视图和图层记忆。
- 用户 GPS 的 WGS-84 与高德 GCJ-02 统一转换，避免几百米定位偏移。
- 导航从“打开外部地图”扩展为应用内路线预览、下一步提示和外部导航接管。

### 6. 多人协作

- 新增 `trip_collaborator`、`trip_vote`、`trip_activity`。
- 支持邀请码加入共享行程。
- 支持 must / can / skip 投票和冲突聚合。
- 发起人可选择保留、移除或自由活动等仲裁方案。
- 协作者可通过 PlanOps 修改 canonical 行程，版本记录实际操作者。

### 7. Today Mode 与旅行中体验

- 新增今日行程、当前站、下一站、路线时间和节点打卡。
- 支持当天临时重排，仍走 PlanOps Preview / Apply。
- 新增今日预算、账本支出和剩余额度。
- 生成离线 HTML 行程卡，并写入本地离线快照。
- 行程结束后可基于点赞、避雷和实际停留生成偏好建议。
- 偏好建议只有用户显式确认后才写入长期画像。

### 8. 多来源 POI 与数据健康

- 高德继续作为 T1 主地点、路线和导航来源。
- 新增 OSM、Wikidata、Wikivoyage 自动补充。
- 新增地方文旅 CSV/GeoJSON 导入，保留来源、授权、署名和原始记录。
- 新增百度 Place API、腾讯位置服务可选 Provider。
- 百度 BD-09、腾讯/高德 GCJ-02 坐标分别转换，统一聚合。
- 外部数据自动合并，不要求普通用户选择或点击数据源。
- 新增 `/plan/health`，展示数据库、高德、模型、地图、检索、天气、UGC 和外部 POI 状态。
- 新增 `external_poi` 聚合表、来源 ID、授权、置信度、评分、人均、营业时间和图片字段。
- 明确不抓取美团、大众点评、抖音和小红书；这些平台只在取得正式合作接口后接入。

### 9. 桌面与交付

- Electron 版本升级到 `2.0.2`。
- 内嵌 jlink 裁剪 JRE，目标机器不需要安装 Java。
- 默认使用内嵌 H2，也可覆盖为 MySQL。
- 后端以隐藏进程启动，不弹控制台窗口。
- portable 包为单文件 EXE。

## 数据与兼容性

### 坐标约定

| 坐标系 | 用途 |
|---|---|
| WGS-84 | GPS、OSM、Wikidata、Wikivoyage、标准 GeoJSON、底层数据来源 |
| GCJ-02 | 高德、腾讯、LTing 国内地图展示和导航 |
| BD-09 | 百度来源；请求和返回时单独转换 |

### 兼容性变化

- 含 `plan_data` 的行程不再允许走旧正文和旧节点写接口，必须使用 PlanOps。
- AI 的高风险修改必须先 Preview，再由用户确认 Apply。
- 地图、POI 和路线 Key 继续只保存在本机配置文件或环境变量中。
- 不配置百度、腾讯 Key 时自动跳过，不影响高德主流程。

## 已知边界

1. 百度、腾讯连接器已完成，但发布环境没有真实商用 Key；需要在目标账号下完成一次线上字段验收。
2. OSM、Wikidata、Wikivoyage 公共接口无商业 SLA，网络不稳定时会静默降级。
3. 美团、大众点评、抖音、小红书没有通用公开 POI API，当前不依赖抓取。
4. 尚未完成 25.8 消费级发现页、`place_master / place_source` 和网页推荐校验流水线。
5. 住宿具体酒店、实时房价和库存仍为暂缓项。
6. 尚未完成多人长期用户研究和跨 Windows 版本验证。
7. 密码仍为历史明文存储方案，后续应迁移 BCrypt。

## 从 v1.1.9 升级

1. 关闭旧版 LTing。
2. 保留 `%USERPROFILE%\\.ai-travel-assistant\\application.properties` 中的本机 Key。
3. 运行 `LTing-2.0.2-portable.exe`。
4. 在“系统设置 → 商用地点补充”中按需填写 `geo.baidu-key`、`geo.tencent-key`。
5. 重启应用后，在“数据源”面板确认高德、百度、腾讯、外部 POI 和模型状态。
