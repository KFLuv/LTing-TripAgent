## 4. 本轮修复

### 4.1 评测执行器

- 修复创建会话接口返回 JSON 字节串、脚本却按字典读取的问题；
- 新增 `--only`，支持只回归指定用例；
- 每条用例使用独立 CookieJar 和独立游客身份，避免共享行程数据；
- 修正 LT-10 的错误期望：`getBudgetSummary` 是只读工具，不应出现在写操作列表中。

### 4.2 Agent 版本能力

- `saveTrip` 新建行程后生成“初始版本”快照；
- 新增 `updateTrip` 工具；
- 修改已有行程时先备份修改前版本，再写入新正文；
- 更新系统提示，要求修改既有行程时使用 `updateTrip`，只有新建才使用 `saveTrip`；
- `updateTrip` 作为写操作生成可见动作摘要。

### 4.3 服务稳定性

- 修正 `https\://` 环境变量注入导致非法 URL 的问题；
- 将 Tomcat `StandardContext.setSessionTimeout` 的单位从错误的“秒”改为“分钟”；
- 将 `tomcat_sessions.max_inactive` 升级为 `BIGINT`，避免 `max_inactive * 1000` 在 H2/MySQL 中溢出；
- 会话清理观察 75 秒无 numeric overflow。

## 5. 残余 Badcase

### 5.1 导航链接与文本实体不一致

现象：

- 正文写“广州图书馆”，链接目的地可能是南越王博物院；
- 正文写“广东省博物馆”，链接可能跑到北京路。

影响：

- 用户可能被导航到错误地点；
- 自动检查只看“有没有高德链接”，无法发现实体不一致。

下一步：

1. 在 `navigateTo` 结果中保存规范化目的地实体；
2. 回答返回前校验每个链接与相邻实体名是否一致；
3. 对不一致链接用工具返回值覆盖，无法覆盖就删除链接并提示；
4. 增加“链接目的地一致性”评测项。

### 5.2 回退不恢复行程节点

现象：

- `rollbackTrip` 只恢复 `trip.title/content`；
- `trip_node` 的预约、风险、备选路线节点不进入版本快照；
- 用户回退正文后，旧节点仍会存在。

影响：

- 行程正文可能与节点列表冲突；
- 用户可能看到已失效的预约或风险提醒。

下一步：

1. 在 `trip_version` 中保存节点快照 JSON；
2. 回退时同时恢复正文和节点；
3. 或者在节点模型中增加 `version_id / active`，按当前版本过滤；
4. 在修复前，回答必须明确说明“仅正文回退，节点需人工处理”。
