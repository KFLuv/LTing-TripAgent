# LTing Agent 评测方案

## 目的

验证 LTing 不只会生成文字建议，还能在真实会话中完成任务、调用工具、写入资产、回退修改，并在信息不足时拒绝编造。

## 评测集

`lting-eval-cases.jsonl` 包含 10 条任务，覆盖：

- 行程规划；
- 偏好记忆；
- 行程修改；
- 版本回退；
- 缺少定位；
- 附近搜索；
- 导航；
- 多人偏好冲突；
- 实时事实边界；
- 预算记录。

每条用例包含用户输入、预期写操作和人工检查项。

## 指标

| 指标 | 定义 |
| --- | --- |
| 任务完成率 | 人工检查项全部通过的任务数 / 总任务数 |
| 工具调用正确率 | 预期写工具被调用且没有明显误调用的任务数 / 总任务数 |
| 写操作可见率 | 有写操作且有可见动作反馈的任务数 / 有写操作的任务数 |
| 事实边界通过率 | 没有编造实时事实、未知信息明确说明的任务数 / 事实类任务数 |
| 平均响应时间 | 每次 `/agent/chat` 请求耗时均值 |
| 人工接管率 | 需要人工修正或重试的任务数 / 总任务数 |
| 回退成功率 | 回退任务中版本成功恢复的比例 |

Token 和模型成本暂不纳入自动统计，因为当前 `/agent/chat` 响应没有返回 usage 字段。

## 判定口径

- **通过**：任务完成、必要工具调用正确、回答没有明显编造。
- **部分通过**：任务完成但存在多余调用、表达不清或需要人工修正。
- **失败**：未完成任务、写操作缺失、编造事实或无法恢复。

不要用“回答看起来不错”代替评测。每个 Badcase 记录现象、期望、实际、原因和下一步。

## Badcase 记录模板

```text
用例编号：
用户任务：
期望行为：
实际回答：
实际工具调用 / actions：
失败类型：未完成 / 工具错误 / 编造事实 / 写操作缺失 / 回退失败 / 其他
影响：
初步原因：
修复动作：
回归结果：
```

## 执行

先启动本地服务并配置 `AI_API_KEY`，然后运行：

```bash
python scripts/eval_lting.py --base-url http://127.0.0.1:8078/chat
```

只复跑指定用例：

```bash
python scripts/eval_lting.py --base-url http://127.0.0.1:8078/chat \
  --only LT-03,LT-04,LT-10 \
  --output docs/evaluation/lting-eval-regression-20261104.json
```

脚本会使用 `/guest` 建立会话，逐条调用 `/agent/chat`，把原始响应、耗时和自动检查结果写入：

```text
docs/evaluation/lting-eval-results.json
```

自动结果只能判断写操作和基础文本条件，最终成功与否仍需按人工检查项复核。

### 已修复

1. 评测执行器把会话 JSON 字节串误当字典；
2. 本机配置中的 `https\://` 经环境变量注入后成为非法 URL；
3. Agent 新建行程没有生成初始版本快照；
4. 缺少“修改已有行程”的 `updateTrip` 工具，模型会重复新建行程；
5. H2 `tomcat_sessions.max_inactive * 1000` 的整数溢出；
6. 预算用例把只读 `getBudgetSummary` 错当成写操作；
7. 多链接回答中导航文案与目的地可能不一致；
8. 回退只恢复正文，不恢复节点；
9. 手工编译缺少 `-parameters` 导致 `@RequestParam` 参数名丢失；
10. 领域入口 `trip(action=get)` 的 `tripId/id` 参数映射错误。
