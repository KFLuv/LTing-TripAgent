# A 组：对话历史落库

## 问题

`AgentController.java` 把对话历史存在 `HttpSession` 内存里,关闭浏览器即丢失,导致每次对话都是全新的。

## A1 建表

在 `AgentSchemaInitializer.java` 中**仿照现有 `CREATE_*` 常量的写法**新增一张表:

```sql
create table if not exists chat_message (
    id          bigint auto_increment primary key,
    username    varchar(64) not null,
    role        varchar(16) not null,        -- user / assistant
    content     mediumtext  null,
    create_time datetime    not null,
    index idx_chat_user (username, id)
) default charset=utf8mb4;
```

**只存 `user` / `assistant` 的纯文本。禁止存 `tool_calls` 或 `role=tool` 的消息** —— 回放时会触发「tool_calls 无对应 tool 响应」的 400 错误。

## A2 新增 DAO

新建 `com/iflytek/chatgpt/dao/ChatMemoryRepository.java`（若项目无 `dao` 包，放到 `util` 包下）：

```java
public class ChatMemoryRepository {

    /** 取最近 limit 条，按时间正序返回（用于回放上下文） */
    public List<JsonNode> loadRecent(String username, int limit) {
        List<JsonNode> list = new ArrayList<>();
        String sql = "select role, content from ("
                   + "  select role, content, id from chat_message"
                   + "   where username = ? order by id desc limit ?"
                   + ") t order by id asc";
        try (Connection c = MySQLUtil.getConnection();
             PreparedStatement ps = c.prepareStatement(sql)) {
            ps.setString(1, username);
            ps.setInt(2, limit);
            try (ResultSet rs = ps.executeQuery()) {
                while (rs.next()) {
                    ObjectNode m = JsonNodeFactory.instance.objectNode();
                    m.put("role", rs.getString("role"));
                    m.put("content", rs.getString("content") == null ? "" : rs.getString("content"));
                    list.add(m);
                }
            }
        } catch (SQLException e) {
            log.error("读取对话历史失败: username={}", username, e);
        }
        return list;
    }

    public void append(String username, String role, String content) {
        if (content == null || content.isEmpty()) return;
        MySQLUtil.executeUpdate(
            "insert into chat_message(username, role, content, create_time) values(?,?,?,now())",
            username, role, content);
    }

    public void clear(String username) {
        MySQLUtil.executeUpdate("delete from chat_message where username = ?", username);
    }
}
```

## A4 新增历史接口

在 `AgentController.java` 新增：

```java
@PostMapping(value = "/agent/history", produces = "application/json;charset=UTF-8")
public Map<String, Object> history(@RequestParam(defaultValue = "20") int limit,
                                   HttpSession session) {
    Map<String, Object> r = new LinkedHashMap<>();
    String username = ChatController.currentUser(session);
    if (username == null) {
        r.put("login", "false");
        r.put("messages", java.util.Collections.emptyList());
        return r;
    }
    r.put("login", "true");
    r.put("messages", chatMemoryRepository.loadRecent(username, Math.min(limit, 100)));
    return r;
}
```

## A5 前端拉取并渲染

文件：`frontend/chat.html`

在页面初始化（`mounted` 或 DOMContentLoaded）里新增：

```js
async loadHistory() {
  try {
    const res = await fetch('agent/history?limit=20', { method: 'POST', credentials: 'include' });
    const data = await res.json();
    if (!data.login) return;
    (data.messages || []).forEach(m => {
      this.addMsg(m.role === 'user' ? 'me' : 'ai', m.content, { silent: true });
    });
    this.scrollToBottom();
  } catch (e) { /* 静默失败，不阻塞页面 */ }
}
```

> `silent: true` 表示渲染历史消息时**不触发额外的网络请求或欢迎语**。若 `addMsg` 无此参数，需自行加一个 `opts` 形参并跳过副作用。

# B 组：AI 动作可见

## B1 后端返回执行记录

文件：`TravelAgentService.java`

**当前** `run(...)` 返回 `String`。改为返回结构体（**保留原 `String` 版本作为内部方法，避免影响其他调用方**）：

```java
public static class AgentResult {
    public String answer;
    public List<Map<String, String>> actions = new ArrayList<>();
}
```

在 `runLoop(...)` 中，**每次执行工具后追加一条记录**：

```java
// 在执行 dispatch 之后
String summary = describeAction(toolName, args);   // 见下
if (summary != null) result.actions.add(Map.of("tool", toolName, "summary", summary));
```

`describeAction` 只对**写操作**生成中文摘要，读操作返回 `null`（避免刷屏）：

| `saveTrip` | `保存行程：{title}` |

# D 组：Agent 参数调优

## D1 `MAX_ROUNDS` 6 → 12

文件：`TravelAgentService.java`

```java
private static final int MAX_ROUNDS = 12;   // 原为 6
```

**原因：** 一次"行程变更"需要 `listPreferences` → `listTripNodes` → 查开放时间 → 算时间 → `saveTripNode` → 输出风险清单，共 6 步。原值 6 刚好用完，导致「读得到但写不回去」。

## D2 提示词最前面加铁律

在 `SYSTEM_PROMPT` **开头**插入：

```
【最高优先级铁律 —— 违反即为回答失败】
1. 涉及行程变更、画像更新、同行人记录、收藏、预算、清单的需求，
   必须先调用对应工具写入真实数据，再给出文字说明。
   禁止只给文字建议而不落库。
2. 每次回答前，先用 listTrips / listTripNodes / listPreferences 读取当前真实状态，
   不要凭记忆回答。
3. 写完后必须回报「已写入什么」，让用户能在对应页面看到变化。
4. 涉及空间距离，必须基于真实坐标算距离，不推测。
5. 本地无数据时标注来源，不编造；查不到就换更宽的词再试一次。
```

## D3 提示词重排

当前四大引擎在第 3–8 行，大量「怎么查附近」的叮嘱在后面。模型对靠近末尾的指令更敏感，导致引擎定义被盖过。

**改成三段式：**

```
【身份】          1 段，20 字内
【铁律】          D2 的内容，放最前
【输出结构】      现有一段
【四大引擎能力】  移到末尾（模型记得最牢）
```
