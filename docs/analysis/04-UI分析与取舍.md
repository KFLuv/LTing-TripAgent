> **给人看的。** 给 agent 的执行规范见 [`AI旅游助手-UI优化规范.md`](AI旅游助手-UI优化规范.md)。

# 一、问题不在审美，在"没有系统"

**实测你的 `chat.html`（2391 行）：**

| 维度 | 实测 |
|---|---|
| 硬编码颜色 | **87 处 / 48 种** |
| `rgba()` | **38 处 / 32 种** |
| 字号 | **12 种**（12 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15 / 16 / 18 / 19 / 22 / **5**） |
| `padding` | **27 种 / 30 处** |
| `border-radius` | **12 种**，只有 1 处用变量 |
| `box-shadow` | **13 种** |
| `transition` | **10 种** |
| `line-height` | **9 种** |

**关键点:** 你已经定义了 8 个 CSS 变量（`--ink` / `--brand` / `--radius` 等）—— **说明你有这个意识**，但**没执行到底**：变量只用在少数地方，其余全是字面值。

> **同样的元素在不同位置长得不一样，整体就"土"。**
> 这不是调几个颜色能解决的。

**两个可以直接确认的问题:**
- 🔴 **`font-size: 5px` 是笔误**（应该是 12px 或 13px）
- 🔴 **`padding` 27 种 / 30 处** —— 意味着几乎每个元素的间距都是随手写的

---

# 二、治法：把值收敛成令牌

**核心动作只有一个:用一套有限的令牌替换所有字面值。**

| 维度 | 现在 | 收敛后 |
|---|---|---|
| 字号 | 12 种 | **7 种** |
| 间距 | 27 种 | **8 种**（4 的倍数） |
| 圆角 | 12 种 | **5 种** |
| 阴影 | 13 种 | **5 种层级** |
| 动效时长 | 10 种 | **3 种** |
| 颜色 | 48 种 | **约 25 种语义色** |

**验收标准:改完后文件里 `#` 开头的颜色字面值应少于 10 处**（只允许出现在 `:root` 里）。

**为什么这一步能让 UI 立刻"贵"起来：**
- 令牌是**有意图的**（`--sp-4` 是 16px，不是"随便写个 15px"）
- 令牌**成体系**（间距都是 4 的倍数 → 视觉上有节奏）
- 令牌**可维护**（改一处影响全局）

# 三、四个观感提升最大的组件

## ① 消息气泡 —— 最影响第一眼

**现状:** 有 `.message` 系列样式，但圆角、内边距、头像尺寸不统一。

**要改两点:**

| 改动 | 效果 |
|---|---|
| **收角方向区分 AI / 用户** | AI 收左下角、用户收右下角 → **一眼看出谁说的** |
| **最大宽度用 `min(px, %)`** | 宽屏不拉到整行，窄屏自动收窄 |

```
AI   ┌──────────────────────┐       用户        ┌────────────────┐
     │ 白底 + 细边框 + 轻阴影 │                   │  品牌色实底     │
     └──────────────────────┘◀收角              └────────────────┘◀收角
```

## ② 快捷入口 —— 从纯文字按钮改成卡片网格

**现状:** 6 个入口是纯文字（`定制行程` / `周边吃喝玩乐` / `一键导航` / `目的地推荐` / `记住偏好` / `我的行程本`）。

**改成:** 图标 + 标题 + 一行说明的卡片，hover 上浮 + 描边。

**关键收益:** 用户**点之前就知道每个入口干什么**。

> `记住偏好` → 改为 **`我的偏好`**，说明写「**查看和修改记住的习惯**」。
> 现在的写法让用户以为是"设置"，实际是**查看已有画像**（这也是上一份文档里"偏好不可见"的一部分）。

## ③ 空状态 —— 当前完全没有

**现在打开聊天页无消息时是一片空白。** 这是最容易被忽略但**最影响第一印象**的一处。

**要加两处:**
1. 聊天区无消息 → 图标 + 「开始你的旅行规划」+ 下方快捷卡片
2. 「我的行程本」为空 → 图标 + 「还没有保存的行程」+ 「去规划一个」按钮

## ④ 顶部栏 + 输入区 —— 一行 CSS 的毛玻璃

```css
backdrop-filter: saturate(180%) blur(14px);
```

> **注意:这是现代浏览器标准能力，不是液态玻璃那种 WebGL 方案，成本极低。**

# 四、关于 PathPilot 那份液态玻璃指南

**你手上有一份 `liquid-glass-web-guide.md`（PathPilot 的）。我读了 —— 但对你不适用。**

| | PathPilot 的场景 | 你的场景 |
|---|---|---|
| 效果 | iOS 26 液态玻璃（WebGL 折射 + 弹簧物理） | 常规 Web UI |
| 依赖 | 自建 WebGL 着色器 + 离屏上下文 + 解析解弹簧 | 无 |
| 成本 | 极高（那份指南里全是踩坑） | 低 |
| 收益 | 视觉惊艳但要"背后有东西可折射" | 不适用 |

**那份指南里的关键警告（第 0 节）值得你记住:**

> **"液态玻璃的效果只有在背后有东西可以折射时才看得见。在纯色背景上，透镜折射纯色还是纯色，什么都看不出来。"**

**你的界面正好是纯色背景** —— 硬上玻璃效果只会得到一个"糊"的界面。

**但指南里有一条通用原则对你直接适用:**

> **"不要凭感觉做，要逐项移植一个可信的参考实现。"**

**这也正是我给你的方案:不凭感觉调色，先把值收敛成系统。系统立住了，再谈风格。**

# 五、执行顺序（8 批，每批截图验证）

| 批 | 内容 | 验收 |
|---|---|---|
| **1** | 替换 `:root` 令牌块 | 外观**不应有明显变化**（令牌值≈原值） |
| **2** | 全局字面值 → 令牌替换 | 颜色字面值 < 10 处;删掉 `font-size:5px` |
| **3** | 消息气泡 | AI / 用户气泡**方向可辨** |
| **4** | 顶部栏 + 输入区毛玻璃 | 输入框聚焦有蓝色描边 |
| **5** | 快捷入口改卡片 | hover 上浮 + 描边 |
| **6** | 空状态 | 无消息时有引导 |
| **7** | 弹窗 + 滚动条 | — |
| **8** | 响应式 3 断点 | 820px 下侧栏变抽屉 |

> **第 1 批是"外观不变"的重构** —— 这一步不改观感，只是把地基打好。
> **从第 3 批开始才有肉眼可见的变化。**
>
> 建议按顺序做，**每批截图**。一次全改完，出问题无法定位是哪批引入的。

# 六、给 agent 划的红线

我在规范里写明了这些禁止项，理由一并给你:

| 禁止 | 原因 |
|---|---|
| ❌ 引入 Tailwind / UI 框架 / 新字体 | 你的前端是原生 HTML，引入框架会重构整个项目 |
| ❌ 引入 WebGL / Canvas 特效 | 纯色背景下没效果，只有成本 |
| ❌ 改任何 JS 逻辑 | 本次只动样式与结构，避免破坏功能 |
| ❌ 用 `!important` | 说明选择器结构有问题，是在掩盖 |
| ❌ 加暗色模式 | 工作量大一倍，本次不涉及 |
| ❌ 用渐变遮丑 | 渐变不解决间距与层级，只会更花 |

**另外三条硬约束:**
- 只改 `frontend/`，不碰后端
- 不改 DOM 结构（除快捷入口加 `desc`、新增空状态块）
- **不执行任何 git 操作**
