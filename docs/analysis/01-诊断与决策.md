> **这份文档是给人看的**:说明我为什么这么改、优先级怎么定的。
> **给 agent 执行的版本**见 [`AI旅游助手-修复任务指令.md`](AI旅游助手-修复任务指令.md)。

# 一、核心结论

**你的能力都做出来了,但链路没接上。**

| 指标 | 实测 |
|---|---|
| 后端接口 | **57 个** |
| 前端实际调用 | **14 个** |
| **前端从未调用** | **44 个（77%）** |
| 数据表 | 14 张 |
| **前端从未提及的表** | **14 张（100%）** |
| 前端页面 | **1 个页面 + 3 个弹窗**（`chat.html` 一个页面,加"编辑信息/行程本/行程详情"三个弹窗） |
| Agent 注册工具 | 30 个 |
| `MAX_ROUNDS` | 6 |

> **产品完成了 77% 的后端能力,却只展示了 23%。**

**你"感受不到"不是错觉,是三个可量化的断点。**

# 二、为什么"感受不到" —— 三个断点

## 断点一:对话历史不落库

**证据**（`AgentController.java`）:

```java
/** 会话内记忆存放在 session 里的 key */
List<JsonNode> history = (List<JsonNode>) session.getAttribute(SESSION_HISTORY);
if (history == null) { history = new ArrayList<>(); session.setAttribute(...); }
```

| 数据 | 存储 | 关浏览器后 |
|---|---|---|
| 对话历史 | 🔴 **HttpSession 内存** | **丢失** |
| GPS 位置 | 🔴 **HttpSession**（注释写着"不落库"） | **丢失** |
| 行程 / 画像 / 同行人 | ✅ MySQL | 保留 |

**所以"每次进来都是新的"是必然的** —— session 一失效,`history` 变空,模型看不到任何上文。

## 断点二:AI 不真的写库

| 指标 | 实测 | 问题 |
|---|---|---|
| 工具数 | **30 个** | 超出模型有效选择范围（经验值 10–15） |
| `MAX_ROUNDS` | **6** | "读 + 算 + 写"跑不完 |
| 强制落库规则 | **无** | 模型默认选最省力的"说话" |

**一次"起晚了"的完整链路:**

```
listPreferences（画像）      → 轮1
listTripNodes（现有节点）     → 轮2
查开放 / 预约时间             → 轮3
算时间是否来得及              → 轮4（可能还要 searchWeb 查备选）
saveTripNode（写回行程）      → 轮5
setTripStatus / 输出风险清单  → 轮6  ← 满了
```

**6 轮刚好够"读一遍",不够"算一遍 + 写回去"。**

**佐证:** 提示词里专门写了一大段"附近查询必须调 `searchNearby`""本地库查不到必须调 `searchWeb`" ——
**这两段的存在本身就说明模型不主动调,你才要反复叮嘱。**
而 `listTripNodes` / `saveCompanion` / `getBudgetSummary` **没有任何叮嘱,模型自然几乎不碰。**

## 断点三:偏好不可见 ← 最直接对应"记不住我的习惯"

**后端 7 个偏好接口:**

```
/preference/template/save|list|copy|delete|activate
/preference/item/save|delete
```

**前端 `chat.html` 实际调用的:**

```
agent/available · agent/location · agent/chat · destinations
myinfo · updateUserInfo
trips/save · trips/list · trips/get · trips/deletes
```

> 🔴 **`preference/*` 一个都没调。**

**界面上关于"偏好"的全部内容只有四处:**

| 位置 | 内容 |
|---|---|
| `:1272` | 弹窗副标题:"更新您的账户安全信息和**旅行偏好**设置"（只是一句话） |
| `:1484` | 快捷入口 `{id:'pref', icon:'fa-heart', title:'记住偏好'}` |
| `:1495` | 欢迎语里提到"**记住你的旅行偏好**" |
| `:1762` | 点了那个入口 → **只发一条文本** `this.sendText('我想设置我的旅行偏好')` |

**而提示词要求"静默更新画像"** —— 三个"静默"叠加 = **用户永远感觉不到它在记。**

> **"静默"这个设计是错的。记忆看不见,用户就不信它有记忆。**
>
> **PathPilot 正好相反:** 把 AI 提取的内容先落成「**待确认**」,用户确认后才生效,并在界面上显示。**看得见,才会觉得"它在学我"。**

## 断点四:AI 做了什么完全不可见 ← 最隐蔽

```
用户说"帮我记住我不吃辣"
   ↓
后端：savePreference(username, "饮食忌口", "不吃辣")   ← 真写了库
前端：一个聊天气泡「好的，已记住您不吃辣」              ← 只有文字
用户：没有偏好页 → 无法验证
```

**你的 Agent 有 30 个工具、会真的改数据,但界面上只显示一个聊天气泡。工具调用过程零可见性。**

# 三、六个「做了但完全露不出来」的功能域

> 判定标准:**前端零调用 + 前端零提及**。

| # | 功能域 | 后端投入 | 前端 |
|---|---|---|---|
| **①** | **游记生成** `travelog` | **38 处引用（所有表里最高）** + 3 接口 | 🔴 零 |
| **②** | **工具箱**（证件 / 清单 / 预算） | 36 处 + 11 接口 | 🔴 零 |
| **③** | **收藏**（夹 + 项） | 17 处 + 6 接口 | 🔴 零 |
| **④** | **偏好画像 + 模板** | 41 处 + 7 接口 | 🔴 零 |
| **⑤** | **行程节点 + 版本回退** | 25 处 + 8 接口 | 🔴 零 |
| **⑥** | **同行人 + 投票** | 5 处 + **连 HTTP 接口都没有** | 🔴 零 |

## 最可惜的两处

**1. 「AI 生成游记」**

`travelog` 是你所有表里**引用最多**的（38 处），有 `generate` / `list` / `get` 三个接口。
**用户根本不知道它能生成游记。**

**2. `trip_version` + `rollbackTrip`**

**你的 prompt 里根本没要求"变更可回退",但你做了版本快照和一键回滚。**
这是**超做的产品设计**,用户永远发现不了。

> **这两项投入产出比最高 —— 后端全做完,只差一个入口。**

# 四、三处「重复 / 多余」

## ① `/Aichat` 与 `/agent/chat` 并存 ⚠️ 最危险

| 接口 | 实现 | 能力 |
|---|---|---|
| `/Aichat` | `AiChatService.chat()` | 一次问答,**无工具、无循环** |
| `/agent/chat` | `TravelAgentService.run()` | 有循环、30 个工具 |

```js
const res = await fetch(ready ? 'agent/chat' : 'Aichat', { ... });
```
```java
result.put("available", loggedIn && configured);   // 未登录 or 未配 Key → 静默降级
```

**降级后用户看不出区别（都是聊天气泡），但此时所有 Agent 能力全部失效。**

> ⚠️ **如果 API Key 没配好,你会用旧的桩回复测整个产品,然后得出"产品不行"的结论。**
>
> 这是最值得警惕的一条 —— 它会让你的调试走上完全错误的方向。

**建议:** 降级时界面显式提示「当前为简易模式,管家能力不可用」+ 一个「去配置」按钮。

## ② `/chat/guest` 访客登录 —— 接口有,前端不调
## ③ `GET /captcha` 图形验证码 —— 接口有,前端不调

**两个都是"要么接上,要么删掉"。**

## ④ 同一份数据,两套独立实现

| 数据 | HTTP 接口（给 UI） | Agent 工具（给 AI） |
|---|---|---|
| 行程 | `/trips/*` | `saveTrip` / `listTrips` |
| 偏好 | `/preference/item/*` | `savePreference` / `listPreferences` |
| 收藏 | `/favorites/item/*` | `saveFavorite` / `listFavorites` |
| 预算 | `/toolbox/budget/*` | `saveBudgetEntry` |
| 清单 | `/toolbox/packing/*` | `savePackingTemplate` |
| 日志 | `/travel-log/*` | `logCheckin` / `listTravelLogs` |

**风险:两条路径的校验逻辑可能不一致**（越权判断、字段长度限制会漂移）。

**建议:** Agent 工具内部**直接调用对应的 Service 方法**,而不是各写一份 SQL。**只有一处校验。**

# 五、工具合并方案（30 → 约 12）

> **不是删功能,是合并入口。** 用 `action` 参数承载细分。

| 现在（分散） | 合并为 |
|---|---|
| `listPreferences` + `savePreference` | **`preference(action: get/set/list)`** |
| `listTripNodes` + `saveTripNode` + `setTripStatus` + `listTripVersions` + `rollbackTrip` | **`itinerary(action: list/upsert/status/versions/rollback)`** |
| `listCompanions` + `saveCompanion` | **`companion(action: list/upsert)`** |
| `saveFavorite` + `listFavorites` | **`favorite(action: list/save)`** |
| `saveBudgetEntry` + `getBudgetSummary` + `setBudgetThreshold` | **`budget(action: add/summary/threshold)`** |
| `savePackingTemplate` + `listPackingTemplates` | **`packing(action: list/save)`** |
| `listTravelLogs` + `logCheckin` + `genTravelog` | **`travellog(action: list/checkin/generate)`** |
| `listTrips` + `getTripDetail` + `saveTrip` | **`trip(action: list/detail/save)`** |
| `listPreferenceTemplates` + `activatePreferenceTemplate` | **`preferencetemplate(action: list/activate)`** |
| `saveDocument`（独立） | 保留 |
| `searchDestination` / `searchNearby` / `searchWeb` / `navigateTo` / `getLocationGuide` | 保留（空间类不合并） |

**结果:30 → 约 12 个。模型工具选择准确率会明显上升。**

# 六、提示词重排：为什么顺序很关键

**当前排布:**

| 行 | 内容 |
|---|---|
| 第 3–8 行 | ⬅ **四大引擎定义在这里** |
| 第 9 行起 | 大段「附近查询必须…」「具名目的地不得反问定位…」「本地库查不到必须…」 |

**模型对靠近末尾的指令更敏感。** 所以被记住的是"怎么查附近",而"我是四大引擎联动的管家"被盖过了。

**同时:** 提示词 3151 字符 / 19 行,四大引擎的定义**挤在第 3–8 行,密度极高**(每条引擎一段长句)。

**建议三段式:**

```
【身份】          1 段，20 字内
【铁律】          5 条，放最前
【输出结构】      现有一段
【四大引擎】      移到末尾 ← 模型记得最牢
```

> 用于自查"哪条引擎有壳没芯"。

## ③ GPS 现场向导

| Prompt 要求 | 代码 | 状态 |
|---|---|---|

# 九、一句话总结

> **产品完成了 77% 的后端能力,却只展示了 23%。**
>
> **最值钱的两个隐形功能是「AI 生成游记」和「行程版本回退」** ——
> 前者投入最大（38 处引用,全表最高）,后者是你**超做的设计**,用户都发现不了。
>
> **最隐蔽的问题是:AI 真的改了数据,但界面上只显示一个聊天气泡,用户无法验证它做了什么。**
>
> **最危险的问题是:未配 API Key 时会静默降级到旧桩 —— 你可能一直在测一个没有 Agent 的版本。**
