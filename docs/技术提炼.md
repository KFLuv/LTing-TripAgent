### 3. AI 当前是怎么接进来的

核心只有一个类：[AiChatService.java](本仓库源码)

它做三件事：

1. **读配置**：从 `application.properties` 读 `ai.base-url`、`ai.api-key`、`ai.model`。
2. **拼请求**：按 OpenAI 兼容协议拼 `{model, messages:[system,user]}`，POST 到 `base-url + /chat/completions`，Header 带 `Authorization: Bearer <api-key>`。
3. **取结果**：从响应 JSON 的 `choices[0].message.content` 里取出纯文本。

配置文件写法（[application.properties](本仓库源码)）：

```properties
server.port=8078
server.servlet.context-path=/chat

# 换厂商只改这三行
ai.base-url=https://api.deepseek.com
ai.api-key=
ai.model=deepseek-flash
```

> **为什么能"换厂商只改三行"**：智谱、讯飞星火、硅基流动、阿里百炼、DeepSeek、Groq、OpenAI 全都兼容 `chat/completions` 这套协议，只要 `base-url` 填到域名级（代码会自动补 `/chat/completions`）即可。

调用点只有一处 —— [ChatController.java](本仓库源码) 的 `/Aichat`：

```java
@PostMapping(value = "/Aichat", produces = "text/plain;charset=UTF-8")
public String aiChat(@RequestBody(required = false) String userMessage) {
    if (aiChatService.isConfigured()) {
        try {
            return aiChatService.chat(userMessage);   // 走真实大模型
        } catch (Exception e) {
            return "抱歉，AI 服务暂时不可用：" + e.getMessage();
        }
    }
    // 没配 key 时的本地兜底模板，保证功能不挂
    return "感谢您的咨询！...";
}
```

前端在 [chat.html](本仓库源码) 里这样调用：

```js
const response = await fetch('Aichat', {          // 相对路径 → /chat/Aichat
    method: 'POST',
    headers: { 'Content-Type': 'text/plain' },
    body: message
});
const aiResponse = await response.text();
```

**注意**：到这里为止，这只是"**调用大模型**"，还不是"**Agent**"。区别见下一章。

## 第二部分：怎么把项目接入 Agent

### 4. 先搞清楚：LLM 调用 ≠ Agent

| 对比项 | 普通 LLM 调用（现状） | Agent |
| --- | --- | --- |
| 输入 | 一句话 | 一句话 + 一组可调用的**工具** |
| 模型能做什么 | 只能"说" | 能"**决定去做什么**"，然后真的去做 |
| 是否读数据库 | 不能 | 能（通过工具） |
| 是否多轮 | 一问一答 | **循环**：想 → 调工具 → 看结果 → 再想 → 直到完成 |
| 是否记上下文 | 无 | 有（Memory） |

**一句话公式**：

```
Agent = LLM（大脑） + Tools（手脚，即 function calling） + Loop（循环） + Memory（记忆）
```

分水岭就是 **Tools / Function Calling**：让模型返回"我要调用哪个函数、参数是什么"，由**你的 Java 代码**去执行，再把结果喂回给模型继续推理。

### 5. 四步接入（可直接照做）

下面假设你现在要在这个旅游项目里做一个"**能自己查景点、自己存行程的旅行规划 Agent**"。

#### 第 1 步：把现有能力封装成"工具"

工具的本质就是：**一个方法 + 一段给模型看的说明书（JSON Schema）**。

这个项目里已经天然有 3 个工具候选，直接复用，不用重写：

| 工具名 | 复用已有的 | 作用 |
| --- | --- | --- |
| `searchDestination` | `DestinationController` 的查询逻辑 | 按关键词查景点 |
| `saveTrip` | `TripController.save` | 把规划好的行程存进行程本 |
| `listTrips` | `TripController.list` | 列出用户已存行程 |

建议新建一个专门的包来放工具（**这就是"文件放哪"的答案**）：

```
com/iflytek/chatgpt/agent/
├── tool/
│   └── TravelTools.java        # 工具的具体实现（被 Agent 循环调用）
├── AgentTool.java              # 工具的"说明书"（名字+参数+描述）
└── TravelAgentService.java     # ★ Agent 循环主体（想→调工具→再想）
```

`TravelTools.java` 骨架：

```java
package com.iflytek.chatgpt.agent.tool;

import org.springframework.stereotype.Component;
import util.MySQLUtil;
import java.sql.*;
import java.util.*;

@Component
public class TravelTools {

    /** 工具1：按关键词搜景点 */
    public List<Map<String, String>> searchDestination(String keyword) {
        List<Map<String, String>> list = new ArrayList<>();
        String sql = "select name, city, category, description from spot"
                + " where name like ? or city like ? or keywords like ?";
        try (Connection conn = MySQLUtil.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            String like = "%" + keyword + "%";
            for (int i = 1; i <= 3; i++) ps.setString(i, like);
            try (ResultSet rs = ps.executeQuery()) {
                while (rs.next()) {
                    Map<String, String> m = new LinkedHashMap<>();
                    m.put("name", rs.getString("name"));
                    m.put("city", rs.getString("city"));
                    m.put("category", rs.getString("category"));
                    m.put("description", rs.getString("description"));
                    list.add(m);
                }
            }
        } catch (SQLException e) {
            throw new RuntimeException(e);
        }
        return list;
    }

    /** 工具2：保存行程 */
    public String saveTrip(String username, String title, String content) {
        MySQLUtil.executeUpdate(
                "insert into trip(username, title, content, create_time) values(?,?,?,now())",
                username, title, content);
        return "已保存到行程本，标题：" + title;
    }
}
```

`AgentTool.java` —— 给模型看的说明书：

```java
package com.iflytek.chatgpt.agent;

public class AgentTool {
    private String name;        // 函数名，要和工具实现一一对应
    private String description; // 模型靠这句话决定"什么时候用这个工具"
    private String parameters;  // JSON Schema 字符串，描述参数

    // 构造 + getter/setter 省略
}
```

对应上面两个工具的 Schema（**这段是给模型看的，不是给人看的**）：

```json
[
  {
    "type": "function",
    "function": {
      "name": "searchDestination",
      "description": "根据关键词（城市名、景点名、分类如'滨海度假'）搜索旅游目的地",
      "parameters": {
        "type": "object",
        "properties": {
          "keyword": { "type": "string", "description": "搜索关键词" }
        },
        "required": ["keyword"]
      }
    }
  },
  {
    "type": "function",
    "function": {
      "name": "saveTrip",
      "description": "把最终确定的行程方案保存到用户的行程本",
      "parameters": {
        "type": "object",
        "properties": {
          "title":   { "type": "string", "description": "行程标题，20字以内" },
          "content": { "type": "string", "description": "行程正文，按天列出" }
        },
        "required": ["title", "content"]
      }
    }
  }
]
```

#### 第 2 步：请求里带上 tools

在 `AiChatService` 里加一个重载方法（原来的 `chat()` 保持不动，避免破坏现有功能）：

```java
public String chatWithTools(List<JsonNode> messages, String toolsJson)
        throws IOException, InterruptedException {
    ObjectNode body = objectMapper.createObjectNode();
    body.put("model", model);
    body.set("messages", objectMapper.readTree(objectMapper.writeValueAsString(messages)));
    body.set("tools", objectMapper.readTree(toolsJson));   // ★ 关键：把工具清单递过去
    body.put("tool_choice", "auto");                       // 让模型自己决定用不用

    // ... 发请求的代码和原来 chat() 一模一样 ...
    return response.body();   // ★ 注意：这次原样返回整个 JSON，不再只取 content
}
```

#### 第 3 步：写 Agent 循环（最关键的一段）

模型不会自己执行工具，**是你执行、再把结果喂回去**。这个往复过程就叫 Agent Loop：

```java
package com.iflytek.chatgpt.agent;

@Service
public class TravelAgentService {

    private static final int MAX_ROUNDS = 5;   // ★ 必须设上限，防止死循环烧钱

    private final AiChatService aiChatService;
    private final TravelTools travelTools;

    public String run(String username, String userInput) {
        List<JsonNode> messages = new ArrayList<>();
        messages.add(systemMsg("你是旅行规划助手，可以调用工具查景点、存行程。"));
        messages.add(userMsg(userInput));

        for (int round = 0; round < MAX_ROUNDS; round++) {
            String raw = aiChatService.chatWithTools(messages, TOOLS_JSON);
            JsonNode choice = read(raw).path("choices").path(0);
            JsonNode message = choice.path("message");

            // 情况 A：模型没调工具，直接给了最终回答 → 结束
            if (message.path("tool_calls").isMissingNode()
                    || !message.path("tool_calls").isArray()) {
                return message.path("content").asText();
            }

            // 情况 B：模型要调工具 → 把它的"调用请求"原样放进历史
            messages.add(message);

            // 逐个执行
            for (JsonNode call : message.path("tool_calls")) {
                String toolName = call.path("function").path("name").asText();
                JsonNode args = read(call.path("function").path("arguments").asText());

                String result = dispatch(username, toolName, args);   // ★ 这里才是"真正干活"

                // 把执行结果作为 role=tool 的消息塞回历史，模型下一轮才能看到
                messages.add(toolMsg(call.path("id").asText(), result));
            }
            // 循环继续：带着工具结果再问一次模型
        }
        return "规划超时，请把需求说得再具体一点～";
    }

    /** 工具名 → 真正的 Java 方法 */
    private String dispatch(String username, String toolName, JsonNode args) {
        switch (toolName) {
            case "searchDestination":
                return toJson(travelTools.searchDestination(args.path("keyword").asText()));
            case "saveTrip":
                return travelTools.saveTrip(username,
                        args.path("title").asText(), args.path("content").asText());
            default:
                return "未知工具：" + toolName;
        }
    }
}
```

这段循环的逻辑，画出来是这样：

```
用户提问
   │
   ▼
┌─────────────────────────────┐
│ 请求模型（带上 tools 清单）  │◄──────────┐
└─────────────┬───────────────┘           │
              ▼                           │
      模型返回 tool_calls？                │
        │是                    │否         │
        ▼                      ▼           │
  执行 Java 工具         直接返回文字答案   │
        │                                │
        └── 结果塞回 messages ────────────┘
```

#### 第 4 步：暴露一个接口给前端调用

```java
package com.iflytek.chatgpt.controller;

@RestController
public class AgentController {

    private final TravelAgentService travelAgentService;

    public AgentController(TravelAgentService travelAgentService) {
        this.travelAgentService = travelAgentService;
    }

    @PostMapping(value = "/agent/chat", produces = "text/plain;charset=UTF-8")
    public String chat(@RequestBody String userMessage, HttpSession session) {
        String username = ChatController.currentUser(session);
        if (username == null) {
            return "请先登录后再使用智能规划";
        }
        return travelAgentService.run(username, userMessage);
    }
}
```

前端只要把 `fetch('Aichat', ...)` 换成 `fetch('agent/chat', ...)`，其它一行都不用改。

### 6. 文件放哪 / 谁调用谁（速查表）

| 文件 | 放在哪 | 作用 | 被谁调用 |
| --- | --- | --- | --- |
| `application.properties` | `resources/` | 存 `ai.base-url / api-key / model` | Spring 启动时注入 `@Value` |
| `AiChatService.java` | `.../chatgpt/service/` | 拼 HTTP、发请求、取结果 | `ChatController` / `TravelAgentService` |
| `TravelTools.java` | `.../chatgpt/agent/tool/` | 工具的真实实现（查库、写库） | `TravelAgentService` 的 `dispatch()` |
| `TravelAgentService.java` | `.../chatgpt/agent/` | **Agent 循环主体** | `AgentController` |
| `AgentController.java` | `.../chatgpt/controller/` | 对外 HTTP 接口 | 前端 `fetch('agent/chat')` |
| `chat.html` | `resources/static/` | 界面，发请求、渲染结果 | 浏览器 |

调用链：

```
浏览器 chat.html
   └─ fetch POST /chat/agent/chat
        └─ AgentController.chat()
             └─ TravelAgentService.run()
                  └─ 循环 {
                       AiChatService.chatWithTools()   → 调大模型
                       TravelTools.searchDestination() → 查 MySQL
                       TravelTools.saveTrip()          → 写 MySQL
                     }
```

### 7. Memory（记忆）怎么做

Agent 的"记忆"就是 `messages` 这个列表。三种常见做法：

| 做法 | 实现 | 适用 |
| --- | --- | --- |
| 会话内记忆 | 把 `List<JsonNode> messages` 存进 `HttpSession`，下次接着用 | 简单、够用（本项目推荐） |
| 长短期记忆 | 新建 `chat_history` 表，按 `username` 存历史，每轮取最近 N 条 | 需要跨会话 |
| 摘要记忆 | 历史太长时让模型先总结成一段话再带上 | 对话很长时省 token |

会话内记忆的改法（最省事）：

```java
// AgentController 里
List<JsonNode> history = (List<JsonNode>) session.getAttribute("agentHistory");
if (history == null) {
    history = new ArrayList<>();
    session.setAttribute("agentHistory", history);
}
return travelAgentService.run(username, userMessage, history);
```

### 8. 工程化注意事项（踩坑清单）

1. **一定要设 `MAX_ROUNDS`**。模型可能反复调工具，不设上限会一直循环、一直扣钱。
2. **工具执行必须 try-catch**。工具抛异常时，把错误信息当成 `role=tool` 的结果返回给模型，模型能自己纠正（比如换个关键词再查一次），而不是整个接口 500。
3. **`arguments` 是字符串不是对象**。`call.function.arguments` 拿到的是 JSON **字符串**，必须再 `readTree()` 解析一次。
4. **`tool_call_id` 必须回填**。构造 `role=tool` 的消息时，`tool_call_id` 要和模型给的 `id` 完全一致，否则厂商会直接报 400。
5. **越权防护**。凡是带用户数据的工具（存行程/查行程），`username` 必须由后端从 `session` 取，**绝不能让模型或前端传**。本项目 `TripController` 已经是这个写法，照抄即可。
6. **成本与延迟**。带工具的请求模型会"先思考再调用"，比普通问答慢、贵。建议：能一次问完的别用 Agent，需要"查数据 + 多步推理"才用。
7. **超时**。`AiChatService` 里已设 `connectTimeout=10s`、请求 `timeout=60s`；Agent 循环总耗时是各轮之和，前端 loading 文案要说明"可能需要几十秒"。
8. **配置为空要兜底**。`AiChatService.isConfigured()` 判断三项配置是否齐全，缺任何一项就走本地模板，保证 demo 不挂。

### 9. 怎么验证 Agent 真的生效

1. 故意问一个**必须查库**才能答的问题，比如"帮我找找三亚有哪些景点"。
   → 看后端日志应该出现一次 `searchDestination` 的执行记录，说明工具被调用了。
2. 再问"把刚才的行程存起来"。
   → 去数据库执行 `select * from trip order by id desc limit 5;` 应该能看到新记录。
3. 如果模型一直不调工具、只会聊天：
   - 检查 `tools` 字段是否真的传了；
   - 检查工具 `description` 是否说清了"什么时候用"；
   - 检查当前 `ai.model` 是否支持 function calling（DeepSeek、GLM、GPT 系列都支持）。

## 附：本项目构建方式（无 Maven 时）

如果目标机器没有 Maven，可以只做「编译 + 重打 fat jar」两步：

```python
# 1) 从现有 fat jar 抽出 BOOT-INF/lib/*.jar 当 classpath
# 2) javac -parameters -encoding UTF-8 -cp <libs> -d classes <sources>
# 3) 重写 jar：先写 META-INF 与 org/，再写 BOOT-INF/classes/
#    （含目录条目），最后写 BOOT-INF/lib/
```

**三个必须注意的点：**

| 点 | 原因 |
|---|---|
| **必须加 `-parameters`** | 否则 Spring 解析不到 `@RequestParam` 的参数名，所有带参接口 500 |
| **不能用 `--release 8`** | 代码用了 Java 11 的 `java.net.http`，会被整包屏蔽 |
| **必须写目录条目** | `BOOT-INF/classes/` 及其子目录，否则 `ClassNotFoundException` |
| **`BOOT-INF/classes/` 要排在 `BOOT-INF/lib/` 之前** | 否则 Spring Boot 启动器定位不到应用类 |
